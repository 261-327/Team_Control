# Сипи: локальный запуск на Windows без Docker

Нужны **Python 3.11+**, **Node.js 24 LTS** и два терминала **PowerShell**. Права администратора и изменение Execution Policy не нужны. Эти команды сверены с кодом проекта; сам запуск на Windows пока не проверен — разработка и проверки выполнялись на macOS.

## 1. Открыть проект

Открой в VS Code папку **Team_Control**, внутри которой лежат `backend`, `frontend` и `README.md`.

Если проект уже скачан, **не удаляй его**: в нём могут быть твои изменения и локальная база. Если Git не установлен, проект можно получить через **Code → Download ZIP** на [GitHub](https://github.com/261-327/Team_Control) или клонировать средствами Visual Studio. Для запуска уже скачанного проекта Git не обязателен.

Если по прежней инструкции заменил условие выбора базы в `backend/config/settings.py` на `if True:`, верни именно эту строку:

```python
if os.environ.get("DB_ENGINE") == "sqlite":
```

Другие изменения в файле не стирай. SQLite включается переменной окружения, а не изменением кода.

## 2. Первый PowerShell: Django

Открой **новый PowerShell в корне Team_Control**. Проверь:

```powershell
Test-Path .\backend\manage.py
py -3 --version
node --version
```

Первая команда должна показать `True`, Python — версию не ниже 3.11, Node — установленную версию 24. Если `py` не найден, но `python --version` показывает подходящую версию, в команде создания окружения ниже используй `python` вместо `py -3`.

В этом же терминале выполни по очереди; если команда завершилась ошибкой, сначала разберись с ней:

```powershell
py -3 -m venv .\backend\.venv
.\backend\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt

$env:DB_ENGINE = "sqlite"
$env:DJANGO_DEBUG = "true"
$env:EMAIL_BACKEND = "django.core.mail.backends.console.EmailBackend"
$env:FRONTEND_URL = "http://127.0.0.1:3000"

.\backend\.venv\Scripts\python.exe .\backend\manage.py migrate
.\backend\.venv\Scripts\python.exe .\backend\manage.py runserver 127.0.0.1:8000 --noreload
```

Оставь терминал открытым. Виртуальное окружение активировать не требуется: мы напрямую запускаем его Python.

## 3. Второй PowerShell: интерфейс

Открой **ещё один новый PowerShell в корне Team_Control**, а не в папке `backend`. Проверь корень:

```powershell
Test-Path .\frontend\package.json
```

Должно быть `True`. Затем выполни:

```powershell
Set-Location .\frontend
$env:DJANGO_API_URL = "http://127.0.0.1:8000"
npm.cmd ci
npm.cmd run dev -- --hostname 127.0.0.1 --port 3000
```

Дождись готовности сервера и открой **http://127.0.0.1:3000**. Используй этот адрес последовательно, не переключаясь на `localhost` во время входа. `npm.cmd` позволяет запускать npm без изменения политики PowerShell.

## 4. Регистрация и код входа

Нажми **«Создать аккаунт»** на сайте. Укажи собственные почту, логин и пароль. Письмо с шестизначным кодом появится **в первом терминале, где работает Django**, примерно так:

```text
Ваш код: 123456
```

Здесь `123456` — пример, введи код из своего терминала. Он действует 5 минут. В локальном режиме письмо не отправляется в настоящий почтовый ящик.

Суперпользователь для обычного тестирования **не нужен**. Он не отменяет подтверждение кода на сайте, а аккаунт без email не сможет пройти обычный вход.

Новая SQLite-база будет пустой: аккаунты и проекты с чужого компьютера автоматически в неё не переносятся. После входа создай свой тестовый проект и задачи; предустановленный «Проект на семестр» появляться не должен.

## Если возникла ошибка

- **«Отправка писем пока не настроена», 503:** останови Django через `Ctrl+C`, в **его же терминале** снова задай `$env:EMAIL_BACKEND = "django.core.mail.backends.console.EmailBackend"` и повтори команду `runserver`. Переменная из второго терминала в первый не передаётся. Для локального кода внешний почтовый сервис не нужен.
- **«next не найден»:** проверь, что `npm.cmd ci` завершилась успешно именно в `frontend`. Не пропускай установку зависимостей.
- **Ошибка подключения к PostgreSQL / хост `db` не найден:** в терминале Django перед `migrate` и `runserver` должна быть задана `$env:DB_ENGINE = "sqlite"`.
- **Сайт висит или не связывается с сервером:** проверь, что оба терминала продолжают работать без ошибок. Адрес http://127.0.0.1:3000/api/health должен вернуть `{"status":"ok"}`. Если нет, пришли полный текст ошибки из Django и интерфейса.
- **Порт уже занят:** сначала останови прежний запуск в его терминале через `Ctrl+C`; не запускай новые копии поверх старых.

## Остановка и повторный запуск

Нажми **Ctrl+C в каждом из двух терминалов**. Для следующего запуска в тех же окнах достаточно последних команд `runserver` и `npm.cmd run dev ...`: окружение и зависимости уже установлены. Если терминалы закрывались, снова задай перечисленные переменные окружения и проверь текущие папки.

`./start.sh`, `./stop.sh` и `./setup-ai.sh` рассчитаны на macOS/Linux. Не используй Git Bash как обходной способ их запуска в Windows.

Эта инструкция запускает сайт, API и локальную базу. **ИИ на Windows настраивается отдельно**: нужны Ollama, модель и обработчик запросов, а для картинок ещё модель генерации. Для входа, проектов, задач и доски они не нужны; недоступность ИИ сама по себе не означает, что не запустился сайт.
