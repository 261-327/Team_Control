# Свое направление разработчика — #103

Ветка: feat/103-custom-developer-direction, база main fdcb55e.

В общей форме RoleFields можно выбрать стандартное направление или «Своё направление».
Один компонент используется для создания проекта, приглашения и смены своей/чужой
профессии. Права и политика вступления остаются прежними: самостоятельный join
запрещён, вступление выполняется принятием приглашения.

API использует прежний ключ specialization. Пример тела PATCH
/api/projects/1/my-role/ (данные вымышленные):

```json
{"profession":"developer","specialization":"Разработка игр","customRole":""}
```

В ответе snapshot.memberships для этого участника:

```json
{"projectId":"1","userId":"2","role":"member","profession":"developer","specialization":"Разработка игр","customRole":""}
```

Пробелы по краям удаляются; пустое или полностью пробельное направление
разработчика отклоняется. Максимум 100 символов. Старые backend/frontend/ios/android
сохраняются и читаются как прежде. Смена профессии на другую очищает направление.
Применить миграцию 0024_custom_developer_direction перед запуском новой версии.

Проверка: 50 Django-тестов прошли на отдельной SQLite БД, включая стандартные
направления, границы 100/101, пробелы, создание, принятие приглашения, редактирование,
выдачу snapshot/состава и запрет изменения чужой роли участником.
makemigrations --check --dry-run: изменений нет. ESLint компонентов пройден.
