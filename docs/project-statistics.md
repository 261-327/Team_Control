# Статистика задач проекта — #111

Версия сайта 0.2.0. База a63250d. Вкладка «Статистика»:
/projects/:projectId/statistics. Доступна всем, кто может просматривать проект.

Источник данных — GET /api/bootstrap/ и snapshot ответов изменения задач.
Нового endpoint и дополнительного запроса всей базы нет. Сервер фильтрует snapshot
по правам проекта; ProjectLayout и экран статистики также скрывают недоступный
проект. После изменения задачи клиент публикует snapshot, статистика пересчитывается.
Изменения другого пользователя поступают при очередном обновлении DataProvider.

Метрики считаются по всем задачам проекта, не по странице или фильтру доски:
- total: уникальные задачи проекта;
- completed: status=done; остальные, включая пользовательские этапы, активные;
- overdue: существующая urgency(task, serverNow) = overdue, строго раньше now;
  выполненные задачи, задачи без срока и срок ровно now не просрочены;
- withoutDeadline: нет deadlineAt, включая завершённые;
- процент: округление completed/total*100, для пустого проекта 0;
- по этапам: реальные названия колонок, включая пользовательские, и нулевые этапы.

Это действующая политика обзора команд, а не новое толкование is_completed старых
HTML-колонок. Для изменения политики завершения нужен отдельный согласованный
контракт; здесь done остаётся единым ключом выполнения нового интерфейса.
Общий summarizeTasks используется также карточками обзора команд (#27), общая
urgency переиспользована. Нагрузка обзора учитывает всех исполнителей.

Задача учитывается один раз в общей сводке и один раз у каждого исполнителя.
assigneeIds используется при наличии, иначе старый assigneeId. Пустой массив
означает отсутствие назначений. Дубликаты ID исполнителей удаляются. Суммы строк
участников могут превышать total. Участники без задач включены с нулями; отдельно
показаны задачи без исполнителей и с назначениями вне текущего состава.
Последние входят в общую сводку, но не создают строки бывших участников.

Обезличенный фрагмент входа bootstrap:

```json
{"now":"2026-11-17T12:00:00Z","tasks":[{"id":"1","projectId":"1","status":"todo","deadlineAt":"2026-11-16T12:00:00Z","assigneeId":"2","assigneeIds":["2","3"]}]}
```

При единственной такой задаче total=1, completed=0, overdue=1; у каждого из двух
исполнителей total=1. Это фрагмент snapshot, не полный ответ нового API.
