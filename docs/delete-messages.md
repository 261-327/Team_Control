# Удаление своих сообщений — #109

Версия 0.2.0. Ветка feat/109-delete-own-messages.

## Правила

Комментарий удаляет только автор при текущем доступе к проекту. Руководитель
не получает право удалять чужое обсуждение. Комментарий физически удаляется,
CommentNotification удаляются каскадно, счётчики snapshot пересчитываются.
История событий задачи, сама задача и её материалы не удаляются.

В помощнике удаляется пара «свой запрос + связанный ответ», черновик и бинарная
сгенерированная картинка этой пары. Задачи/проекты, созданные по ответу, остаются.
Активный queued/running запрос сначала нужно отменить существующей кнопкой отмены.
DELETE turns/:id/ по-прежнему означает отмену, его контракт не меняется.

Загруженные файлы принадлежат личному thread и остаются после удаления пары,
поскольку могут использоваться другими сообщениями. Удалённая M2M-связь не удаляет
объект файла. Отдельное удаление вложения или очистка всей переписки — прежние
действия. В последующих запросах удалённая пара не выбирается как история.
Контекст, уже переданный провайдеру для другого запроса, отозвать нельзя.
Отмена/удаление не может восстановить пару поздним результатом worker: worker
обновляет только существующую running запись. Это не обещание удаления данных
из внешних журналов провайдера.

Действия требуют подтверждения; ошибка сервера отображается в ConfirmDialog,
диалог остаётся доступен для повтора. Состояние UI меняется после успеха.

## API (session cookie + CSRF)

DELETE /api/tasks/1/comments/2/ — без тела; 200 {"snapshot": ...}.
Автор + действующий доступ обязательны: чужой комментарий 403, нет доступа к задаче
404. Повтор удаления отсутствующего комментария в доступной задаче возвращает
200 и актуальный snapshot. Для отсутствующей/недоступной задачи — 404.

DELETE /api/assistant/turns/11111111-1111-4111-8111-111111111111/message/
— без тела; 200 {}. Чужой и отсутствующий UUID дают одинаковый 200 {}, не раскрывая
наличие чужой истории и не удаляя её. Для собственного, но недоступного scope —
404. Активная генерация — 409 conflict с предложением отменить. Повтор безопасен.
Без сессии 401, без CSRF 403. Примеры ID вымышленные, реальные cookie не сохранять.

## Редактирование комментария

PATCH /api/tasks/:taskId/comments/:commentId/ принимает text и originalText.
Только автор с действующим доступом может изменить текст (1–2000 символов).
Вложение, автор и время создания сохраняются; editedAt появляется при реальном
изменении. Новые уведомления при правке не создаются. Повтор того же текста не
меняет editedAt; несовпадение originalText с текущим текстом даёт 409 conflict.
Ответ: актуальный snapshot. В UI есть сохранение, отмена и отметка «Изменено».
57 серверных тестов и браузерный сценарий редактирования с reload прошли.
Скриншот: evidence/109-edit-comment.png. Миграция: 0028_comment_edited_at.
