# Резервный профиль: Vercel + Render

Сайт, база и ИИ работают в облаке; постоянно включённый компьютер команды не нужен. Конфигурация сохраняет Django API и существующий интерфейс Next.js. Это небольшой учебный пилот в пределах бесплатных квот, а не обещание бесплатной неограниченной работы.

| Сервис | Что размещается | Настройка |
| --- | --- | --- |
| Vercel Hobby | Next.js и прокси `/api` | Корень `frontend`, Node.js 24, Fluid compute |
| Render Free | Django и вызовы облачного ИИ | Один Python Web Service из корня репозитория |
| Neon Free | Постоянная PostgreSQL-база | Регион рядом с Render, SSL, pooled connection |
| Cloudflare Workers AI Free | Текст и концепты логотипов | REST API, две разрешённые модели, дневная квота |
| Brevo Free | Письма с кодом и восстановлением пароля | Подтверждённый отправитель и transactional API |

В репозитории нет настроенных аккаунтов и настоящих ключей. Наличие этих файлов не означает, что стенд опубликован или доставка писем проверена.

## Что подготовить

Нужны аккаунты сервисов и доступ к GitHub-репозиторию `261-327/Team_Control`. Выбирай Free/Hobby; не включай платные планы, платные модели, AI Gateway с оплатой или автоматическое повышение тарифа. Если панель предлагает карту или платный ресурс вместо Free, сначала проверь условия — шаблон такую покупку не требует.

Секреты вводятся только в окружении Render. Они не отправляются в чат, GitHub, screenshots и `NEXT_PUBLIC_*`. Значения `replace-...` в `render.env.example` и `vercel.env.example` не являются рабочими ключами.

Brevo должен разрешить отправку с выбранного адреса. Может понадобиться подтверждение собственного домена, например уже имеющегося домена команды/вуза, и активация transactional platform. Адрес `@gmail.com`/`@yandex.ru` нельзя считать аутентифицированным доменом команды. Без подтверждения отправителя и проверки реального письма вход на общий стенд не считается готовым. Новый платный домен автоматически не покупается.

## 1. База в Neon

1. Создай проект на Free, желательно в Frankfurt или ближайшем доступном регионе. Для первого пилота используй новую пустую базу; перенос реальных аккаунтов требует отдельного плана.
2. В Connect выбери PostgreSQL и pooled connection. URL с `sslmode=require` добавь как `DATABASE_URL` на Render.
3. Пароль и URL не сохраняй в репозитории. Для остановки пилота отключай приложения, а не удаляй базу вместе с данными.

SQLite на файловой системе бесплатного Render не подходит: файлы теряются при перезапуске. Render Free Postgres тоже не используется — его бесплатная база истекает через 30 дней.

## 2. ИИ в Cloudflare

1. Открой Workers AI на Free и выбери Use REST API.
2. Получи Account ID и токен с разрешением Workers AI для этого аккаунта. Не используй Global API Key.
3. На Render задай `CLOUDFLARE_ACCOUNT_ID` и `CLOUDFLARE_API_TOKEN`.
4. Оставь модели из шаблона: текст `@cf/meta/llama-3.3-70b-instruct-fp8-fast`, изображения `@cf/black-forest-labs/flux-1-schnell`.
5. Не подключай платный Workers plan или платные модели. При исчерпании квоты помощник показывает ошибку; платного запасного провайдера нет.

Провайдеру передаются запрос пользователя и ограниченный контекст доступных ему проектов: названия, описания, задачи и выбранные обсуждения. Служебные поля паролей, токенов и email участников не выбираются. Свободный текст может содержать данные, которые в него внесли пользователи. До использования реальных данных согласуйте этот способ обработки с ответственными за проект.

Запрос обрабатывается во время обращения к Django. Ollama, скачивание весов, `assistant_worker` и компьютер команды не нужны. База Neon может засыпать без постоянного опроса очереди. Одновременно выполняются не более двух облачных запросов: следующий сразу получает «Помощник занят», чтобы остальные потоки могли обслуживать сайт, вход и отмену. Постоянной фоновой очереди нет.

## 3. Почта в Brevo

1. Подтверди аккаунт, отправителя и, если требуется, домен; проверь доступ к transactional emails.
2. Создай API key и добавь на Render как `BREVO_API_KEY`.
3. `DEFAULT_FROM_EMAIL` должен совпадать с разрешённым отправителем. `EMAIL_BACKEND` уже задан как `tasks.email_backends.BrevoEmailBackend`.

На бесплатном Render SMTP-порты заблокированы. Используется HTTPS API, поэтому `EMAIL_HOST` и SMTP-пароль не нужны. Console/file backend подходят для локальных тестов, но не для входа настоящих пользователей на общем сайте.

## 4. Интерфейс в Vercel

1. Попробуй импортировать существующий репозиторий, выбрать ветку с этой конфигурацией и **Root Directory: `frontend`**. Для `261-327` может потребоваться разрешение владельца организации на GitHub App Vercel. Не переходи на Pro ради импорта: если Hobby запрещает репозиторий организации или доступ пока не согласован, используй личный fork с той же веткой и актуальными изменениями. Основной командный репозиторий остаётся на месте.
2. План — Hobby для некоммерческого учебного пилота, framework — Next.js, Node.js — 24. Установка `npm ci`, сборка `npm run build`.
3. `frontend/vercel.json` включает Fluid compute и один регион Frankfurt. Не выбирай Static Export: наш `/api` выполняется на сервере.
4. Создай первое развёртывание и сохрани выданный Production URL. До подключения Django интерфейс может показывать ошибку связи — это промежуточный этап.

Фактический адрес сайта понадобится в Render. Не придумывай его по названию проекта: используй URL из панели Vercel.

Официальные страницы Vercel описывают ограничения GitHub organisations по-разному: [Git](https://vercel.com/docs/git#using-hobby-teams) отдельно запрещает private organization repos на Hobby, а [Limits](https://vercel.com/docs/limits#connecting-a-project-to-a-git-repository) формулирует запрет для organization repos в целом. Поэтому прямой импорт публичного репозитория проверяется в панели; личный fork остаётся бесплатным запасным вариантом. Разрешение GitHub App и допустимость тарифа — отдельные условия. При использовании fork синхронизируй нужную ветку перед обновлением сайта; Django и frontend должны собираться из совместимых версий.

## 5. Django в Render

1. Создай Blueprint из существующего репозитория и нужной ветки. Файл — корневой `render.yaml`.
2. В списке должен быть только один Web Service `sipi-api` с **plan: free**. База, диски, фоновые workers и модели на Render не создаются.
3. Заполни запрошенные значения:
   - `DATABASE_URL` из Neon;
   - `FRONTEND_URL` — точный Production URL Vercel без завершающего `/`;
   - `CSRF_TRUSTED_ORIGINS` — тот же адрес с `https://`;
   - ключ и подтверждённый отправитель Brevo;
   - Account ID и токен Workers AI.
4. Django Secret Key генерируется Render. `DJANGO_ALLOWED_HOSTS` при запуске берётся из фактического `RENDER_EXTERNAL_HOSTNAME`; для собственного backend-домена задай hostname явно.
5. Успешный deploy должен завершиться работающим Gunicorn и проверкой `/api/livez/`.

Сборка устанавливает обычные Python-зависимости и собирает Django static. При запуске один экземпляр применяет миграции, затем слушает `$PORT`: один Gunicorn worker, четыре threads, timeout 300 секунд. Миграции не запускаются параллельно в отдельных worker-процессах.

`/api/livez/` проверяет жизнь приложения без запросов к БД. Не заменяй его на DB-health и не добавляй минутный keep-alive: иначе Neon не сможет засыпать и квота будет расходоваться без пользователей.

## 6. Связать интерфейс с Django

1. Скопируй фактический HTTPS-адрес Web Service из Render.
2. В Vercel Environment Variables добавь серверную `DJANGO_API_URL=https://фактический-сервис.onrender.com` для Production.
3. Выполни Redeploy интерфейса, чтобы применить окружение.
4. Браузер обращается только к `/api` домена Vercel. Cookie сессии и CSRF передаются через прокси. Ключи БД, почты и ИИ в Vercel не нужны.

Для Preview deployment не добавляй wildcard в CSRF. Либо настрой конкретный preview-адрес на отдельном тестовом backend, либо проверяй общий стенд по Production URL.

## Проверка живого стенда

Проверяй отдельным тестовым аккаунтом:

1. Интерфейс открывается, `/api/health` возвращает `{"status":"ok"}`.
2. Регистрация отправляет настоящее письмо; правильный код завершает вход, неверный отклоняется.
3. Восстановление пароля отправляет рабочую ссылку и завершает прежние сессии.
4. Проект и задача сохраняются после обновления страницы и перезапуска Render; изменение статуса видно после нового входа.
5. Помощник отвечает по разрешённым данным, создаёт проект/задачи, предлагает редактируемый черновик и генерирует изображение. Созданное сразу видно в списках. Во время ожидания доступны статус и отмена: после подтверждения сервером чат снова принимает сообщения; при неудачной отмене не показывает ложное «Запрос отменён».
6. Посторонний не получает доступ к закрытому проекту; ограничение вступления проверено серверными запросами, не только отсутствием кнопки.
7. Исчерпание квоты ИИ не создаёт выдуманный успешный ответ и не включает платного провайдера.

Не отмечай эти пункты выполненными на основании одной сборки. Для готового стенда нужны фактический URL и результаты проверки.

## Бесплатные ограничения

Официальные условия проверены 3 ноября 2026:

- Vercel Hobby предназначен для личных некоммерческих проектов и имеет месячные лимиты. Fluid compute позволяет функции работать до 300 секунд. Прокси ждёт облачный ИИ до 280 секунд; браузер — до 290 секунд.
- Render Free засыпает после 15 минут простоя; следующее открытие может занять около минуты. Обычный браузерный запрос ждёт до 95 секунд. После сетевой ошибки можно повторить запрос; keep-alive боты для обхода сна не нужны.
- Neon Free ограничивает вычисления, сеть и объём базы. Спящие вычисления не расходуют compute-квоту, постоянный polling держит их активными. Следи за остатком в панели.
- Workers AI Free даёт 10 000 Neurons в день суммарно на текст и картинки — это не фиксированное число запросов. После лимита запросы завершаются ошибкой до следующего окна. Платные модели запрещены этой конфигурацией.
- Brevo Free ограничивает отправку 300 письмами в день. Подтверждение отправителя и допуск transactional platform проверяются отдельно.
- Изображения хранятся в БД и расходуют квоту Neon. При активном использовании потребуется очистка старых тестовых данных или другое хранилище; автоматического платного расширения нет.

Условия меняются. Перед созданием ресурсов сверяй бесплатный тариф и лимиты в панели. Нулевую стоимость можно сохранять в границах квот, но не гарантировать неограниченную доступность.

## Остановка и обновление

Отключи автоматические деплои в панели, если нужно остановить обновления. Для остановки сайта приостанови/удали только web-развёртывание по правилам площадки; базу с данными не удаляй как способ остановки. Резервные копии и восстановление остаются отдельной работой из #16.

При обновлении применяются сохранённые миграции. Откат кода не отменяет миграции БД. Реальные дампы и настройки не добавляются в Git.
