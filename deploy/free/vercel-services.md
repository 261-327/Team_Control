# Vercel Services: Next.js и Django в одном проекте

Это основной бесплатный профиль для небольшого учебного стенда: сайт и API публикуются одним Vercel-проектом и открываются по одному адресу. Services находится в Beta и доступен на всех планах. База — Neon Free, ИИ — Cloudflare Workers AI Free, письма — Brevo Free. Установка Docker не нужна.

Файлы подготовлены; успешная локальная проверка не означает, что облачный стенд уже опубликован.

## 1. Подготовить сервисы

- В Neon создай новую базу на Free рядом с Frankfurt и сохрани pooled PostgreSQL URL с `sslmode=require`. SQLite в Vercel не сохраняет данные между запусками.
- В Cloudflare открой Workers AI на Free, получи Account ID и API token с разрешением Workers AI. Нужны только разрешённые текстовая модель и генератор из шаблона; платных запасных моделей нет.
- В Brevo подтверди отправителя и доступ к transactional emails, получи API key. Может понадобиться подтверждённый домен команды/вуза и активация отправки. Без реального проверочного письма вход не считается готовым.

Cloudflare получает сообщения и ограниченную часть данных доступных пользователю проектов. Пароли и служебные токены не выбираются, но произвольный текст описаний и комментариев может содержать внесённые пользователями данные. Этот облачный режим согласован для пилота.

## 2. Создать проект в Vercel

1. Выбери Hobby и импортируй репозиторий с актуальной веткой. **Root Directory — корень репозитория (`.`), Framework — Services**, конфигурация — корневой `vercel.json`.
2. Если Vercel GitHub App требует разрешения организации `261-327`, потребуется её владелец. Если прямой импорт запрещён на Hobby или доступ пока не согласован, используй личный fork с той же веткой. Покупать Pro для этого профиля не нужно.
3. Не задавай общий Build Command: у Django и Next.js отдельные команды внутри `services`. Node.js — 24; Python закреплён как 3.13 в `backend/.python-version`.
4. Найди фактический Production domain проекта в Settings → Domains. Он понадобится как `FRONTEND_URL`. Первая сборка без окружения может завершиться ошибкой; это ожидаемо, доступ к БД ещё не настроен.
5. В Project Settings → Environment Variables добавь значения из [vercel-services.env.example](vercel-services.env.example) **только для Production**. В Preview не копируй рабочую базу, почту и ключи ИИ.
6. Production Branch должна содержать эту конфигурацию. Выполни Production deployment / Redeploy после сохранения окружения.

В Services-профиле не используется ручная переменная `DJANGO_API_URL`: Vercel внедряет её в frontend из приватного binding к Django. Отдельный `frontend/vercel.json` сохранён для запасного Render-профиля с корнем `frontend`; Services использует настройки из корневого файла.

Документация Vercel описывает доступ к GitHub organisation repos на Hobby неодинаково: проверяй фактический импорт в панели и используй личный fork, если он заблокирован. Основной командный репозиторий переносить не нужно; перед обновлением синхронизируй ветку fork.

## 3. Что происходит при сборке и запросах

Vercel Django preset устанавливает `requirements.txt` и собирает static. Наш `vercel_build.py` сначала проверяет Production-окружение и обязательные настройки, затем один раз выполняет `migrate --noinput`. Миграции не запускаются при каждом запросе. Preview и сборка без ключей завершаются до обращения к рабочей БД. Для Preview впоследствии нужна отдельная база и отдельный профиль.

Все публичные маршруты направлены в Next.js. `/api` проходит через существующий bridge: он добавляет Django завершающий `/`, сохраняет cookies/CSRF и обращается к приватному backend. Публичного маршрута к `/admin`, Django static и legacy-интерфейсу в этом пилоте нет.

Bridge сохраняет служебный prefix binding URL и сам устанавливает `X-Forwarded-Host/Proto`. Django доверяет этим полям только при `SIPI_VERCEL_SERVICES=true`; список допустимых hosts и CSRF origins содержит точные `FRONTEND_URL` и выданные Vercel адреса этого проекта. Масок `*` и `.vercel.app` нет. Cookie защищены HTTPS.

ИИ обрабатывается внутри запроса, без бесконечного worker или локального Ollama. На одном Python-экземпляре одновременно выполняются не более двух запросов ИИ; остальные получают сообщение о занятости. Платформа может создавать несколько экземпляров, поэтому это не общая дневная квота. Общие лимиты Cloudflare всё равно действуют.

## 4. Проверить живой стенд

По фактическому Production URL, отдельным тестовым аккаунтом:

1. Открывается интерфейс; `/api/livez` отвечает `{"status":"ok"}` без запроса к БД.
2. Регистрация, письмо с кодом и вход работают; неверный код отклоняется. Проверена и ссылка восстановления пароля.
3. Проект и задачи сохраняются после обновления страницы и нового развёртывания.
4. Помощник отвечает по разрешённым данным, создаёт проект/задачи, генерирует картинку; созданное сразу появляется в интерфейсе.
5. Отмена доступна во время ожидания ответа и показывает реальный результат сервера.
6. Посторонний не получает доступ к проекту; CSRF-запросы с чужого origin отклоняются.
7. URL binding с фактическими hostname/prefix работает в опубликованном проекте. Изображение скачивается как PNG и помещается в лимит ответа Vercel.

Эти пункты нельзя считать выполненными по одной production-сборке. Внутренний Host binding и маршрутизацию нужно проверить в самом Vercel-проекте.

## Квоты и обновление

Hobby предназначен для некоммерческого использования и имеет месячные лимиты. Python и Node Fluid Functions ограничены 300 секундами; прокси ждёт ИИ до 280 секунд. Локальные веса моделей, постоянные daemon-процессы и хранилище файлов в функции не используются.

Workers AI Free даёт 10 000 Neurons в день на текст и картинки. После исчерпания запросы возвращают ошибку без перехода на платный API. Brevo Free — до 300 писем в день. Neon ограничивает размер базы и вычисления; не запускай keep-alive или постоянный опрос БД. Сгенерированные картинки занимают место в базе.

Бесплатные квоты провайдеров могут меняться. Перед созданием ресурсов проверь Free/Hobby в панели; тарифы автоматически не повышаются кодом. Сборка применяет миграции перед публикацией: изменения схемы должны быть совместимы с ещё работающей версией. Откат кода не отменяет миграции БД. Резервные копии остаются отдельной задачей.
