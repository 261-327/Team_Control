# Матрица ролей и действий

Эта матрица фиксирует предварительные правила интерфейса и API для текущего сценария. Доступ проверяется для каждого проекта отдельно; наличие роли в одном проекте не даёт полномочий в другом.

| Роль в проекте / тип аккаунта                           | Просмотр проекта и задач      | Комментарии | Изменение назначений проекта                   | Управление доской и участниками |
| ------------------------------------------------------- | ----------------------------- | ----------- | ---------------------------------------------- | ------------------------------- |
| Руководитель проекта (`student`, владелец проекта)      | Да                            | Да          | Да                                             | Да, в своём проекте             |
| Преподаватель (`teacher`, подтверждённое членство)      | Да                            | Да          | Нет, если не имеет отдельного права управления | Нет                             |
| Участник проекта (`student` или другой тип с членством) | Да                            | Да          | Нет                                            | Нет                             |
| Сотрудник (`staff`) с явно заданным `scopeProjectIds`   | Да, только проекты из области | Да          | Да, только проекты из области                  | Да, только проекты из области   |
| Пользователь без членства и без области доступа         | Нет                           | Нет         | Нет                                            | Нет                             |

## Смена руководителя и преподавателя

- Назначения может менять руководитель проекта или сотрудник, у которого проект входит в `scopeProjectIds`; API повторно проверяет это право.
- Для руководителя выбирается любой активный аккаунт типа `student`; для преподавателя — любой активный аккаунт типа `teacher`. Выбор не ограничивается текущей областью сотрудника. Это принятое предварительное правило для текущего этапа.
- Один пользователь не может занимать обе роли одновременно. Проект нельзя сохранить без руководителя; преподавателя можно снять.
- Интерфейс показывает явное подтверждение изменений. Назначение координатора руководителем требует дополнительного подтверждения; его роль меняется только в этом проекте.
- Бывший руководитель и бывший преподаватель остаются подтверждёнными участниками проекта с обычной ролью.
- API выполняет смену назначений в одной транзакции и не принимает неактивные аккаунты или аккаунты неверного типа.

## Ограничения преподавателя

Преподаватель может читать закреплённый проект и оставлять комментарии. Приёмка результата задачи и изменение срока в этом предварительном сценарии ему недоступны.

Матрица описывает правила приложения, а не административные полномочия Django.
