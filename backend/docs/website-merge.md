# Совмещение сайта и дополнений личного кабинета

Основные страницы Next.js и JSON API `/api/` сохранены из `fe/sipi/website`.
Страницы Django из `main`, включая доску, личный кабинет, коллег, их профили,
приглашения и уведомления, доступны по `/legacy/`. Их именованные URL продолжают
использоваться в шаблонах. Аккаунты, проекты и Membership общие для обоих интерфейсов.

Приглашения по почте (`Invitation`, UUID) и приглашения коллег
(`ProjectInvitation`, целочисленный идентификатор) сохраняются отдельно.
У проекта связи называются `invitations` и `colleague_invitations` соответственно.
Принятие приглашения коллеги по-прежнему требует выбора роли; до принятия
подтверждённое участие не создаётся.

Сохранены имена и операции обеих цепочек миграций. Миграция 0014 объединяет
0013_custom_statuses и 0012_project_invitations, отмечая workflow-статус `done`
завершающим и сохраняя пользовательские признаки завершения. Миграция 0015 меняет
только обратное имя связи приглашения коллеги. Миграция 0013_custom_statuses
меняет метаданные поля через SeparateDatabaseAndState без пересоздания таблицы:
blank, choices и Python default не требуют изменения SQL-схемы.

Перед обновлением рабочей PostgreSQL сделайте резервную копию. Затем выполните
`python manage.py migrate`. Удалять базу, том Docker или подделывать состояние
миграций через `--fake` не требуется.

Проверяются обе серии Django-тестов и дополнительные сценарии совместимости:
общий профиль в API и Django, сосуществование приглашений, отсутствие доступа до
вступления, перенос задач и исполнителей, сохранение пользовательских статусов.

Миграция 0016_merge_assistant_and_colleagues объединяет эту цепочку с
0014_assistantworker_assistantthread_assistantturn_and_more. Обе существующие
истории сохраняются, включая базы с уже подключённым помощником; операции
повторного создания таблиц помощника не выполняются.
