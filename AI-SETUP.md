# Бесплатный помощник Сипи

Помощник работает на локальных моделях. Платных API и автоматического переключения на платного провайдера нет. Нужны ресурсы вашего компьютера/сервера; аренда оборудования в бесплатность моделей не входит.

## Запуск без Docker

Из корня Team_Control:

```sh
./setup-ai.sh --images
./start.sh
```

Первая команда скачивает Ollama и Qwen3 4B (~2,5 ГБ), устанавливает дополнительные Python-зависимости и загружает SDXL-Turbo (~6,5 ГБ). Последующие запуски используют уже скачанные файлы. Нужен интернет при установке, для ответов и картинок — нет.

Если картинки пока не нужны: `./setup-ai.sh`. Для добавления картинок позже повторите с `--images` и перезапустите `./start.sh`.

Откройте http://127.0.0.1:3000, войдите обычным аккаунтом и нажмите кнопку помощника справа. Выберите контекст проекта и режим:

- **Обсудить:** вопросы по задачам, участникам, статусам, срокам, комментариям, истории изменений и описаниям материалов.
- **Черновик задач:** план по описанию проекта и вашему сообщению. Отредактируйте поля, выберите исполнителей, уберите лишние задачи и подтвердите создание. Создавать на доске может руководитель или координатор с правами на этот проект.
- **Придумать лого:** опишите знак и цвета. Картинка сохранится в переписке; её можно скачать в PNG. Это концепт 512×512, не готовый векторный фирменный знак; модель не рассчитана на точные надписи.

`start.sh` запускает Django, Next.js и отдельные обработчики чата и картинок. Если Ollama уже работает, используется существующий сервис. Остановка скрипта завершает только запущенные им процессы. Пользовательские проекты и аккаунты хранятся в прежней базе.

## Сервер с Docker

Обычный локальный стек уже включает Ollama, загрузку Qwen и обработчик чата:

```sh
docker compose up --build -d
```

Для вашего боевого стека с существующей PostgreSQL используйте инструкции в `deploy/README.md`, добавив генерацию картинок:

```sh
docker compose --env-file .env.server -f compose.server.yaml -f compose.images.yaml up --build -d
```

Если база работает в Docker volume, добавьте также `-f compose.server-db.yaml` согласно прежней инструкции. Не меняйте имя/адрес существующей базы.

Для локального Compose с картинками: задайте `DJANGO_SECRET_KEY` в `.env` и выполните `docker compose -f compose.yaml -f compose.images.yaml up --build -d`.

На Linux с NVIDIA Container Toolkit можно добавить `-f compose.images-gpu.yaml`. Без GPU обработка картинок может быть медленной. На Mac GPU используется при нативном запуске через `start.sh`; Docker Desktop на Mac не предоставляет этот GPU контейнерам.

Веб-интерфейс доступен, пока модели скачиваются. При первой установке дождитесь завершения `model-init` и `image-init`. Индикатор готовности проверяет модель и отдельные обработчики. Порты Ollama наружу не опубликованы.

## Данные и история

Все запросы проходят через Django с сессией и CSRF. История разделена по пользователю и выбранному проекту. При каждом обращении проверяется текущий доступ; после удаления участника старые ответы и изображения этого проекта ему недоступны. Удаление переписки удаляет её картинки и черновики, но сохраняет созданные на доске задачи.

Модель получает актуальные выдержки из доступных проектов и точные общие количества задач. При больших проектах выбираются релевантные задачи и ближайшие сроки; модель знает, что это выборка. Содержимое внешних ссылок (Figma, GitHub, документы по URL) автоматически не скачивается: используются сохранённые в Сипи названия, описания и ссылки. Пароли, коды входа, SMTP-параметры и email участников в контекст не передаются.

В режиме «Помощник» прямой запрос «создай проект … и 5 задач» создаёт проект, четыре колонки доски и задачи в Django. «Добавь ещё 2 задачи» использует выбранный или последний созданный проект. Если проект не определён, помощник уточнит его. Исполнители и сроки без указания пользователя остаются пустыми. В ответе появляются ссылки на результат, интерфейс обновляется сразу.

Сервер выполняет только два ограниченных инструмента: создание проекта и добавление задач. Права проверяются повторно перед записью; управление чужими проектами через модель невозможно. Создание и запись результата выполняются одной транзакцией: ошибка откатывает весь набор, повторная обработка того же запроса не создаёт копии. Отмена до сохранения блокирует создание. На один запрос — до десяти задач, с учётом лимита колонки.

Режим «Черновик задач» сохраняет прежний порядок: сначала отредактировать и подтвердить. Вопросы, цитаты и просьбы предложить идеи сами по себе не разрешают запись. Уже начатый расчёт модели после отмены может закончиться в фоне.

## Настройки

Для нативного запуска `start.sh` читает `backend/.env`:

```dotenv
ASSISTANT_MODEL=qwen3:4b
ASSISTANT_OLLAMA_URL=http://127.0.0.1:11434
ASSISTANT_TIMEOUT=240
# start.sh включает картинки автоматически, если существует .runtime/image-model.
# ASSISTANT_IMAGES_ENABLED=true
# ASSISTANT_IMAGE_MODEL=/absolute/path/to/model
```

Рабочие файлы и веса находятся в `.runtime/`, исключены из Git. В Docker веса — в именованных volumes `ollama_models` и `image_models`. Не открывайте Ollama в интернет: доступ к нему нужен только Django и обработчикам.

Для отдельного запуска обработчиков с теми же настройками базы:

```sh
backend/.venv/bin/python backend/manage.py assistant_worker --kind chat
backend/.venv/bin/python backend/manage.py assistant_worker --kind logo
```

Если запрос прервался из-за перезапуска, его можно отменить и отправить заново. Зависшие задания переводятся в ошибку обработчиком по таймауту. Лимит — 40 запросов в час на аккаунт и один активный запрос в каждой переписке.

## Модели

- Qwen3 4B: Apache 2.0, https://ollama.com/library/qwen3:4b
- SDXL-Turbo: используем для некоммерческого учебного прототипа; лицензия и ограничения: https://huggingface.co/stabilityai/sdxl-turbo

Перед коммерческим использованием генератора изображений отдельно проверьте его действующие условия. FLUX не выбран по умолчанию: скачивание исходного репозитория требует подтверждения доступа в Hugging Face.
